# begin —— 水声探测算法 C/C++ 复现工程

## 一、bin 原始数据格式（三句话）

1. **文件按帧连续排列**：8 字节文件头之后，是 N 个「72 字节帧头 ＋ 32768 字节数据体」的记录，每帧 **32840 字节**。
2. **一帧的数据体**是 256 通道 × 32 采样点 × float32（小端），排布为**通道优先**：通道 0 的 32 点 → 通道 1 的 32 点 → … → 通道 255 的 32 点，不是「每通道连续存一整帧」。
3. **一帧 = 32 点 = 1 ms**（32 点 ÷ 32000 Hz），所以「帧号 ↔ 时间」按 1:1 换算；文件里存了 256 通道，**实际只有前 128 个有效**，后 128 个是无效通道。

## 二、关键常量

全部定义在 `src/io/bin_format.hpp`，并由 `static_assert` 钉住，**不许在其它文件重写这些数字**。

| 常量 | 值 | 含义 |
|---|---|---|
| `FILE_HDR_BYTES` | 8 | 文件头字节数 |
| `FRAME_HDR_BYTES` | 72 | 每帧帧头字节数 |
| `FRAME_BYTES` | 32840 | 每帧总字节 = 72 ＋ 256×32×4 |
| `FS` / `FRM_NUM` | 32000 / 32 | 采样率 / 每帧点数 |
| `CHAN_NUM` / `USE_CHAN_NUM` | 256 / 128 | 阵列总通道数 / 实际有效通道数 |
| `WORK_PERIOD` | 30 | 主动工作周期 30 s |
| `WORK_PERIOD_CNT` | 960000 | 一周期理想点数 = 30 s × 32000 Hz |
| `Kmax` | 816 | 阵列两端时延对应点数（25.5 ms）＝ 匹配滤波所需的两端余量 |
| `WORK_PERIOD_ALIGN_CNT` | 961632 | 一周期实际读取窗口 = 960000 ＋ 2×816（30051 帧） |
| `CYCLE_FLOATS` / `CYCLE_BYTES` | 123088896 / 492355584 | 一周期落盘的元素数 / 字节数 |

## 三、帧头里的时间字段（72 字节中只用了 12 字节）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 12 | `date` | uint32 | BCD 编码，如 `0x20240929` |
| 16 | `time` | uint32 | BCD 编码，字节序为 百分秒·秒·分·时 |
| 20 | `ns` | uint32 | 纳秒，0 ~ 999999999 |
| 0–11 / 24–71 | 保留 | — | 不使用 |

## 四、怎么验

```bash
./build/test_read readframe              # 读某文件总帧数
./build/test_read cycles                 # 打印全部周期起点（帧号 / 文件 / 起始时刻）
./build/test_read cycle_read 1           # 读第 1 个周期并抽样对拍
./build/test_read cycle_dump 1 out.raw   # 读第 1 个周期并落盘（492,355,584 字节）
```

K1 验收结论：`cycle_dump 1` 落盘的 492,355,584 字节，与 MATLAB 导出的 `ArraySig0`（128×961632 float32）
**逐位一致，最大绝对差 0**（0 / 123,088,896 点不一致）。
